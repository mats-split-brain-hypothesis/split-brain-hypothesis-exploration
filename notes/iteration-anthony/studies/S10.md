## What the bank scores

An item is a non-English description of a concept, read at the final prompt token ("Giresun ve Ordu'da yetişen ...
kuruyemişin adı" -> hazelnut). Two units are **required at the same layer**: `concept` (the English / Chinese name:
hazelnut, 榛子) and `language` (the prompt's language named in English or Chinese, "Turkish" / 土耳其语, or the word in
the source language, fındık). Val: 53 items in 11 languages (ru 10, ar 7, he 7, id 6, ko 6, ...).

## Insights

1. **Every matched centre matches on language, so it subtracts the language.** knnx8's nearest cells share the
   prompt's script and language; pco16's top PCs are language axes (S7 diagnosis: "Arabic", "Indonesia" decode from
   multilingual_mt's PCs); tok's read token is a source-language token. The family mean averages over 11 languages,
   so each item's own language survives subtraction (and is even sharpened: language at L44 0.38 vs zero 0.06). This is
   S6's mechanism mirrored: a mean over cells that share X removes X (S6: the bridge's category; here: the language).
2. **The multilingual_mt guardrail is a language-name check, not a concept check.** On the concept unit, which is the
   unsaid content, pco16 and knnx8 are at least as good as fam (L52 0.62 / 0.58 vs 0.51). The language of the prompt is
   a property of the prompt (visible in its script), though not a prompt token, so the masked control does not catch
   it. -> for the user: report multilingual_mt per unit; a guardrail on the concept unit alone would pass pco16 and
   knnx8. Scorer change, not ours to make overnight; the bench's own rule stands for numbers of record.
3. -> for centres: if the language unit is to be kept, the matching set must span languages (a cross-language kNN, or
   knnx8 restricted to neighbours in another script). Card idea for S4 / A, not run.

## Test (causal): same-language vs other-language family means (`src/jlm/mu/S10.py`)

`samelang`: the family mean over reference cells whose prompt has the read item's `lang` (metadata, not a target);
`otherlang`: over every other language. Read on multilingual_mt and multilingual, fit (@self) and val (@fit).

Prediction (before the run): on multilingual_mt, samelang loses the language unit like knnx8 (L44 <= 0.10) and keeps the
concept (L52 >= fam's 0.51); otherlang keeps the language unit at fam's level or above (L44 >= 0.35). Pass: samelang
<= knnx8 (0.17-0.25), otherlang >= fam (0.34) on val.

multilingual (single-token, the guardrail family near ceiling): every arm 0.93-0.98, no change.

- A family mean restricted to the item's own language reproduces the matched centres' loss exactly where predicted (the
  language unit falls from 0.38 to 0.06 at L44) and **improves the concept** (L56 0.81 vs 0.70, like tok / knnx8 /
  pco16). The mean over the other languages keeps the language unit (0.42) and equals fam on pass.
- So the multilingual_mt guardrail rewards **not** matching the language. A centre can have both only by matching
  everything but the language: e.g. knnx8 / pco16 computed on cells with the language component removed, which needs a
  label-free language direction (the script's tokens give one; not tried).

Note from A (S4, `out/analysis/S4/extra/mt-units.md`): on multihop_mt's 3-hop items every centre removes `bridge2`
(zero 0.67 -> fam 0.22) while knnx8 keeps `bridge1` better than fam (0.38 vs 0.28): S6's mechanism (the family mean
holds the bridges' category) at the unit level.

Cross-study confirmation (B, studies/S5.md, 2026-10-11): adding back / removing the direction of the item's
language-name word moves multilingual_mt's language unit from 0.56 to 0.96 / 0.17 with the concept unit flat. A
diagnostic only (it uses a target unit), but it isolates the same mechanism with a different intervention.
